# Evidence

One row per claim the README makes: the artifact that proves it, and the command
that re-derives that artifact from scratch. Nothing here asks to be taken on
trust — if a row's command does not reproduce its artifact, the claim is wrong and
we would rather you found it than we did.

Commands marked **live** need a DataHub (`npm run datahub:up && npm run seed`).
Commands marked **offline** need nothing but `npm install`, and CI runs all of
them on every push.

The **live** rows are not an exemption. [`prove.yml`](.github/workflows/prove.yml)
boots a real DataHub on a clean Ubuntu runner on every push and runs the live
loop on both catalogs, then fails the build if what it produced disagrees with
what is committed here. So the artifacts below are regenerated by machine, not
merely re-read by it. No API key is involved: nothing in the detection path
calls a model.

## What is not proven here

The README's [*What we haven't proven*](README.md#what-we-havent-proven) section
is part of this document's job, not separate from it. The short version: one
machine, one DataHub version, one operator, **one model** (three passes per case
on it, but still one model — the provider's free-tier daily cap stopped the
second), the `showcase` suite still at one pass, no semantic-drift detection, and
no permissions model on the write-back.
